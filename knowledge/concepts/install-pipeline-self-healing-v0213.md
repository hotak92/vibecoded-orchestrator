# Install Pipeline Self-Healing Improvements (v0.2.13)

Release v0.2.13 hardens the `install.py` launcher-update flow with self-healing mechanisms that prevent users from silently landing on stale binaries, deprecated MCPs, or incomplete update states. Discovered during a v0.2.10→v0.2.12 real-world update test: 8 bugs that would have left end users in a broken state.

[[relatedTo::Orchestrator Install Flow]] [[relatedTo::VCT Launcher]] [[relatedTo::MCP Simplification v0.2.11]]

## Problem Space (v0.2.12)

1. **Stale dist binaries**: `launcher/dist/<os>-<arch>/vct-launcher` could be older than the source tree. After `--update`, users clicking the desktop icon got the wrong version.
2. **Launcher-CLI timeout**: when a stale tier-1 binary (e.g., v0.2.10) didn't recognize v0.2.12's `--register-default-mcps` flag, it launched the GUI instead of the CLI, hit the 30s timeout, and install.py fell straight to the pure-Python fallback (Path B). The tier-3 rebuild that would have worked never ran.
3. **Lost deferrals**: `UPDATE_DEFERRED.md` was written BEFORE late-stage helpers (`_register_mcps`, deprecated-MCP detection, SearXNG checks, etc.) ran, so entries generated by those helpers were silently lost.
4. **Deprecated MCPs preserved**: when install.py dropped Ollama MCP in v0.2.11, existing user installs kept the stale entry in `~/.claude.json`. No automated detection or removal.
5. **`vct-module.json` stale**: version was 0.2.4 (unchanged since v0.2.4-era) while orchestrator shipped v0.2.12. Broke catalog integrity checks.
6. **Store-page version hardcode**: the orchestrator and Pro cards showed `v0.1.6` (hardcoded in Svelte) instead of pulling from the canonical version source (vct-module.json).

## Solutions (v0.2.13)

### Fix 1: Post-Cargo-Rebuild Dist-Binary Auto-Swap

When `--update` runs `cargo tauri build`, the fresh binary often lands in `target/release/` with a newer mtime than the committed `launcher/dist/<os>-<arch>/vct-launcher`. New helper `_refresh_dist_binary_after_rebuild()` detects this and auto-swaps:

- **Gate**: 4 conditions (src exists, src mtime > dist mtime, src was built in THIS run OR version-stale, `--no-binary-swap` not set).
- **Version staleness check**: uses `tauri.conf.json` mtime as a proxy for "dist binary is older than current source".
- **Entry point**: wired into `--update` immediately before `_register_mcps`.
- **Bypass**: `--no-binary-swap` flag skips the swap.

### Fix 2: Tier-3 Retry of Launcher CLI After Timeout

The 4-tier launcher binary resolution path (1: bundled, 2: PATH, 3: cargo rebuild, 4: Python fallback) had a gap: if tier-1 or tier-2 timed out or exited non-zero, install.py went straight to tier-4 (Python) and never tried tier-3.

New behavior in `_register_mcps`:
1. Try Path A (launcher binary CLI) against the current tier-1 binary.
2. If Path A fails (timeout, non-zero exit), invoke `_try_cargo_tauri_build()` explicitly.
3. Retry Path A ONCE with the fresh tier-3 binary.
4. If still failing, fall through to Path B (pure-Python writer).

Emits `register_mcps_tier3_retry` events for observability.

**Flags**:
- `--prefer-only-bundled` — skip tier-2/3 resolution AND the retry.
- `--no-rebuild-on-stale` — skip ONLY the retry; resolution unaffected.

### Fix 3: UPDATE_DEFERRED.md Always Populated

In v0.2.12, the single `_deferral_report.write()` call ran BEFORE `_register_mcps`, deprecated-MCP detection, SearXNG checks, Ollama checks, search-env checks, boot-service materialization, and stale-MCP rewrites. Late-stage deferrals were lost.

Solution: second `_deferral_report.write()` call at the very end of `_run_install` captures all entries. On zero deferrals, writes a stub file with `entries: 0` frontmatter so the user has a paper trail that the run completed cleanly.

### Fix 4: Deprecated-MCP Detection & Consent-Prompted Removal (PR-34)

New `_DEPRECATED_DEFAULT_MCPS` registry maps removed MCPs to their `removed_in` version, reason, and opt-in manifest path. Detection runs unconditionally on `--update`; removal requires explicit `--remove-deprecated-mcps` flag (per-entry consent) or `VCT_REMOVE_DEPRECATED_MCPS=all` env override for CI.

**Pattern**: same scan/detect/remove as PR-33 stale-MCP rewrite.
- Only flags entries whose `command` path is INSIDE install_root (user customizations left alone).
- Two-level backup before any write; atomic `lock + tmp + os.replace` discipline.
- First registry entry: `ollama` (removed in v0.2.11).

See [[MCP Simplification v0.2.11]] for post-removal migration notes.

### Fix 5: `vct-module.json` Version Consistency (Fix 9)

`vct-module.json` was bumped 0.2.4 → 0.2.13 and added to the canonical release-bump checklist (alongside `Cargo.toml`, `tauri.conf.json`, `package.json`). MCP count description fixed: "5 MCP servers" → "4 MCP servers" (post-Ollama removal).

### Fix 6: Store-Page Version Hardcode Removed (Fix 3)

The orchestrator and Pro app cards previously hardcoded `version: '0.1.6'`. New behavior:
- Hardcoded default set to empty string `''`.
- Render guarded by `{#if (catalogVersionById[app.id] ?? app.version)}` so an empty version never shows a bare `v` glyph.
- The catalog override (`list_module_catalog` → `builtin_catalog_entries` → `vct-module.json`) supplies the real version.

### Fix 7: Security (Svelte XSS + devalue DoS)

Bumped Svelte `5.0.0` → `5.55.7` and `@sveltejs/kit` `2.59.1` → `2.60.1` + `devalue` `>=5.8.1` override to close:
- 4 moderate Svelte XSS CVEs (GHSA-pr6f, GHSA-f3cj, GHSA-rcqx, GHSA-9rmh): DOM clobbering, SSR spread attributes, SSR Promise serialization.
- 1 high devalue DoS CVE (GHSA-77vg).

`npm audit` is now clean. svelte-check passes with 0 errors.

### Fix 8: CI Auto-Commit of Dist Binaries

New `.github/workflows/release.yml` job `commit-dist-binaries` (depends on `build`) downloads the 3 OS binaries from matrix artifacts and commits them to main. Skips byte-identical binaries via `cmp -s`.

**Path safety**: stages ONLY `launcher/dist/*/vct-launcher[.exe]` + `.metadata.json` (guards error if non-launcher files sneak in).

**Known issue** (deferred to v0.2.14): the `bypass_actors` ruleset API rejected on personal-account repos. Solution: either move repo to org, or create a `DIST_COMMIT_TOKEN` fine-grained PAT with `Contents: Write` and rework the job to use it.

## Regression Tests

- `tests/test_install_deprecated_mcps.py` — 23 tests for deprecated MCP detection/removal.

Full pytest suite: **1264 passed, 5 skipped, 50 subtests**.

## Flags Summary

| Flag | Effect | Scope |
|---|---|---|
| `--no-binary-swap` | Skip post-cargo dist-binary refresh | Fix 1 |
| `--prefer-only-bundled` | Skip tier-2/3 binary resolution + retry | Fix 2 |
| `--no-rebuild-on-stale` | Skip tier-3 retry (resolution unaffected) | Fix 2 |
| `--remove-deprecated-mcps` | Per-entry consent prompts for deprecated MCP removal | Fix 4 |
| `VCT_REMOVE_DEPRECATED_MCPS=all` | CI mode: remove all deprecated MCPs without prompts | Fix 4 |

## Env Override Reference

| Var | Default | Effect |
|---|---|---|
| `VCT_REMOVE_DEPRECATED_MCPS=all` | (not set) | Auto-remove all deprecated MCPs on `--update` (no prompts) |
