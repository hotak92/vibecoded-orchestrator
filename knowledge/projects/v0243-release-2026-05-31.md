# v0.2.43 — post-update audit fixes + RL weights contract + CI gate hardening

**Base**: `v0.2.42` at `07275c9` (chore(binary) refresh).
**Scope**: 20 items across 4 worktree-isolated agent branches (A–D).
**Headline**: a dedicated live audit run on the actual machine after the v0.2.42 update found 3 additional bugs the static pre-tag review missed. These drive the release.

## Why this release exists

After shipping v0.2.42 and pressing "Update orchestrator" on VCO_dev, a dedicated read-only audit agent (4 sections: A-launcher-db, B-env-config, C-weaviate, D-runtime) inspected the live machine state. It found 3 bugs that passed every static code review, unit test, and pre-tag smoke gate:

1. **A1** — Hub health probe hits the wrong URL (`/health` → 401 instead of `/api/v1/health` → 200). Every v0.2.42 install leaves a stale cutover sentinel in `.vct/`. The test `hub_health_endpoint_exempt_from_auth` hit the *correct* path, masking the bug.
2. **A2** — Full-sync code path writes `nodes_synced: 0` to `app_state.last_kg_sync_stats` even when 1128+ nodes were synced. The diff-only branch recorded stats correctly; the full-sync branch was never wired.
3. **A3** — `module_installs` row stays `status='installed'` when `container_name IS NULL` + `last_error` contains a pull-auth failure. The reconciler checks only `vct-module.json` existence, missing this broken-install shape.

These are the "audit-miss" class: bugs only surfaced by running the software on a real machine post-update, not by reading the code. The lesson is now formalized in MEMORY.md as [[relatedTo::audit-agent-before-multi-agent-fanout]].

## Architecture decision: rl_embed named vector slot (no code change)

Decided during v0.2.43 planning: do NOT add a `rl_embed` named vector slot to Weaviate. The cos3heads architecture uses projection heads on top of text embeddings — storing a separate RL embedding per node would double the embedding cost with no retrieval benefit. Decision: defer indefinitely, revisit only with forensic evidence of retrieval degradation. Documented here so future contributors don't re-litigate.

## Key audit-miss lessons

### 1. Static review cannot catch wrong-URL probes

The `_probe_vct_hub_health` function looked correct in isolation. The test `hub_health_endpoint_exempt_from_auth` exercised `/api/v1/health` — the RIGHT path. No test ran `_probe_vct_hub_health()` against a real hub. The only way to catch this was to run the install flow and grep the logs.

**Rule added**: after every release, run a post-update audit agent against the live machine before declaring the release clean. This should be a standard step in the pre-v0.2.X-checklist scripts going forward.

### 2. Stats code only tested on the happy path

The full-sync branch of `_seed_weaviate` was never exercised in a test that checked the `app_state.last_kg_sync_stats` output. Both the CI smoke tests and unit tests only exercised the diff path (context-unchanged case). Audit caught this because it could query `SELECT value FROM app_state WHERE key = 'last_kg_sync_stats'` directly on the live DB.

**Rule added**: when an observability write (stats, audit log) has two code paths, both must be covered by unit tests that assert the actual value written, not just that the function returns without error.

### 3. Reconciler gap for partial-install shapes

The module reconciler correctly handles "manifest missing → reinstall needed" but not "manifest present + container_name NULL + last_error non-empty" (the install succeeded through the manifest-extraction step but failed at container pull). The static audit couldn't see this because it requires a live DB row with the bad shape — only a live update from a machine where GHCR auth had failed would produce it.

**Rule added**: for container-pull modules, the reconciler MUST check all invariants, not just manifest presence.

## Post-tag user actions required

After the v0.2.43 tag is cut and the update is applied:

1. **Verify sentinel cleanup**: confirm `/home/martino/.vct/v0.2.21-cutover.flag` (or equivalent) is deleted by the startup path.
2. **Verify KG sync stats**: after running `install.py --update`, check `SELECT value FROM app_state WHERE key='last_kg_sync_stats'` — `nodes_synced` should be > 0 for a full-sync run.
3. **Verify RL Reranker reconciler**: `SELECT status, container_name, last_error FROM module_installs WHERE module_id='vct-rl-reranker'` — if `container_name IS NULL` the row should now read `status='broken'` instead of `status='installed'`.
4. **Delete `VibeCodedOrchestrator_KnowledgeGraph` collection and re-verify count**: the v0.2.42 update wrote ~1128 nodes to the shared KG due to the orchestrator-root-is-canonical-shared-KG bug (still tracked). Post-delete count should reflect only legitimate cross-project nodes.

## v0.2.43 CI gate changes

- **Gate 3** added to `pre-release-gate` in `release.yml`:
  - On tag push, asserts `git diff $PREV_TAG..HEAD -- launcher/dist/` is non-empty.
  - Skips (notice, no error) when: no prior tag exists (first release), or `workflow_dispatch` dry-run.
  - Catches the exact v0.2.42 regression: Windows-mut hotfix was retagged, `commit-dist-binaries` 403'd on branch protection, main still carried v0.2.41 binary under v0.2.42 tag, chore(binary) catch-up commit was required before v0.2.43 could be cut.
