# Repo Cleanliness Policy

**Status:** policy doc, normative for contributions.
**Last updated:** 2026-05-06 (PR-4 — privacy + history rewrite)

This repo enforces a hard split between **tracked source-of-truth**
files and **machine-local artifacts**. Anything that was generated
for a specific developer machine — install state, RL training data,
per-machine compose overrides, secrets, agent definitions — must
NEVER be tracked. Templates that get **compiled** into those
machine-local artifacts during install/build DO get tracked, in a
separate top-level directory (`templates/`).

This document is the canonical version of the rules; `.gitignore`
implements them, `copy_recursive_sync` (in
`launcher/src-tauri/src/commands/installer.rs`) honors them at
runtime, and CI grep-checks the shipped binaries to catch
regressions.

---

## 1. Never tracked (machine-local)

These paths are gitignored. Anything in them is for a single user's
machine and must not propagate cross-clone.

| Path | What lives here | Why never tracked |
|---|---|---|
| `state/` | RL training data, blackboard SQLite, sessions, install logs | Per-install, accumulates, big, sensitive |
| `*.pt`, `*.onnx` | RL model checkpoints | Binary artifacts, machine-specific |
| `.venv/`, `venv/`, `ENV/` | Python virtualenv | Generated by install |
| `.claude/agents/` | Per-machine agent definitions | Compiled from `templates/` at install time |
| `.claude/skills/` | Per-machine skill definitions | Compiled from `templates/` at install time |
| `.claude/logs/` | Per-machine tool/cost/failure logs | Local telemetry |
| `.claude/worktrees/` | Per-machine git worktrees | Local |
| `.claude/cron-jobs.json` | Per-machine `/loop` schedule | Local |
| `.claude/context/pre-compact-snapshot.md` | Per-session compaction state | Local |
| `CLAUDE.local.md` | Per-machine private notes | Sensitive |
| `infrastructure/docker-compose.override.{yml,yaml}` | Bug 31 launcher-generated volume override | Per-machine paths |
| `/vct-secrets/` (repo-root) | The `~/.vct-secrets/` primitive copied to repo | Secrets |
| `*.pat`, `*.token`, `*.pem`, `*.key` (except `*.pub.key` / `public.key`) | API tokens, private keys | Secrets |
| `.env`, `.env.*`, `*.env` (except `.env.example`) | Real environment files | Secrets |
| `.vscode/settings.json` (except `.example`) | Per-machine editor config | Local |
| `__pycache__/`, `*.py[cod]`, `.pytest_cache/` | Python build cache | Generated |
| `weaviate_data/`, `ollama_data/` | Local container volume data | Generated |
| `launcher/src-tauri/target/` | Rust build cache | Generated |
| `node_modules/`, `pnpm-lock.yaml`, `launcher/pnpm-lock.yaml` | npm/pnpm artifacts | Generated (npm uses `package-lock.json`) |
| `OSS_LAUNCH_READINESS.md` | Pre-public audit doc | Internal |

## 2. Always tracked (source-of-truth)

Despite living adjacent to gitignored siblings, these paths ARE
source code or upstream-verified content:

| Path | Why tracked |
|---|---|
| `templates/agents/`, `templates/skills/` | Compiled into `.claude/agents/`, `.claude/skills/` at install time |
| `tools/vct-secrets/` (the CLI source) | Repo-root `/vct-secrets/` rule is anchored to NOT match this; explicit `!tools/vct-secrets/**` un-ignore protects against `*.pat`/`*.token` false-positives on test fixtures |
| `launcher/src-tauri/icons/*.png` | Tauri bundle inputs |
| `launcher/static/*.png` | SvelteKit static assets |
| `launcher/dist/<arch>/vct-launcher{,.exe}` | Prebuilt launcher binaries shipped with each release. CI builds them from source; verified clean by leak-check (see PR-4 §A2) |
| `launcher/dist/*/THIRD_PARTY_LICENSES.txt`, `README.md` | Bundle metadata |
| `vendor/lean-ctx/<arch>/lean-ctx{,.exe}` | Third-party binary, verified against upstream SHA256 (see `vendor/lean-ctx/VERSION.md`) |
| `docs/**/*.png`, `knowledge/**/*.png` | Documentation diagrams, screenshots |
| `scripts/check-install.sh` regex matching `/home/martino` etc. | Deliberate self-test for path-leak audit class |
| `tests/test_telemetry.py` fake `ghp_…` tokens | Test fixtures for the PII scrubber — verifies it removes them |

## 3. The PNG / `vct-secrets/` rule conflict (background)

Before PR-4, two over-broad ignore rules silently shadowed legitimate
tracked content:

- `*.png` (line ~96 of pre-PR-4 `.gitignore`) un-ignored only
  `docs/**/*.png` and `knowledge/**/*.png`. The 16 Tauri icon PNGs
  under `launcher/src-tauri/icons/` and the 2 SvelteKit static PNGs
  under `launcher/static/` were tracked but formally ignored. Cosmetic;
  removing-and-re-adding required `git add -f`.
- `vct-secrets/` was meant for the `~/.vct-secrets/` primitive but also
  matched `tools/vct-secrets/` (CLI source). 6 files tracked-but-ignored.

PR-4 fixes both:
- Added `!launcher/src-tauri/icons/**/*.png` and
  `!launcher/static/*.png` exceptions.
- Anchored the rule to repo-root: `/vct-secrets/`. The CLI source under
  `tools/vct-secrets/` is no longer matched, AND `!tools/vct-secrets/**`
  is added belt-and-braces against the `*.pat`/`*.token`/`*.pem`/`*.key`
  rules false-positive-ing on future contributions.

## 4. The `copy_recursive_sync` gitignore-aware contract

The launcher's `update_orchestrator_at` Tauri command copies one
orchestrator install over another (cross-clone update flow). Pre-PR-4
the walker was gitignore-blind, so machine-local files inside kept
allowlist entries (`tools/`, `.claude/`, `infrastructure/`) silently
propagated cross-clone. Specifically:

- `tools/vct-secrets/foo.token` (matched by `*.token` in source's
  `.gitignore` but copied verbatim) — REAL leak risk
- `.claude/agents/coder.md`, `.claude/skills/...`,
  `.claude/logs/2026-05-06_tool_usage.jsonl` — per-machine artifacts
  copied as-if they were source
- `infrastructure/docker-compose.override.yml` — per-machine volume
  config

PR-4 swapped in `ignore::WalkBuilder::standard_filters(true)`, which
honors `.gitignore` + `.git/info/exclude` + `core.excludesFile` +
`.ignore`. The walker still copies untracked-but-not-gitignored files
(matches the conventional "source-of-truth" model: anything you'd
get from `git archive` plus working-tree files that you simply
haven't committed yet).

If the source isn't a git repo (e.g. a bundle extracted from a
release tarball, or a test fixture), the walker falls back to the
old blind copy. This is logged with `[vct] copy_recursive_sync:
source ... has no .git/ ancestor; falling back to blind walker
(gitignored files WILL be copied).` and is the correct behavior for
non-checkout sources because they're already curated.

## 5. CI grep-check for build-host path leaks

`.github/workflows/ci.yml` has a `launcher-leak-check` job that
runs `strings <binary> | grep -E '^/home/[^/]+/'` and similar on
the freshly-built launcher. It fails the build if any non-generic
path matches (the GitHub-hosted runner's `/home/runner/...` is
allowed; `/home/<your-real-username>/...` is not).

Combined with `[profile.release] strip = "symbols"` and the
`--remap-path-prefix` rustflags in `launcher/src-tauri/.cargo/
config.toml`, this is the regression guard for the audit class
"developer machine paths leaked into shipped binary."

### How to rebuild the bundled `dist/` binary safely

There are TWO recurring mistakes that produce a broken or leaky
binary. Both are easy to make and the symptoms are downstream:

1. **Plain `cargo build --release`** (instead of `pnpm tauri build
   --no-bundle`). The cargo command produces a binary that tries to
   load its frontend from `http://localhost:1420` (the Vite dev
   server) at startup. Symptom: the launcher window opens with
   "Could not connect to localhost: Connection refused". Only
   `pnpm tauri build` runs the frontend build pipeline (vite + svelte-
   adapter-static) and embeds the static assets via Tauri's resource
   system, so the WebView can load from `tauri://localhost/` at
   runtime. The `--no-bundle` flag skips installer-bundle generation
   (`.deb`, `.AppImage`, `.dmg`, `.msi`) — those go to GitHub Releases
   later, not into `dist/`.

2. **Forgetting `RUSTFLAGS`**. The checked-in `.cargo/config.toml`
   only remaps OS-level prefixes (`/home`, `/Users`, `C:\Users`).
   Without an env-var-driven per-user remap, the binary embeds your
   username in every `cargo registry` source path. CI doesn't catch
   this on hosted runners (their username is the generic `runner`),
   so the leak only shows up on dev-box rebuilds.

Canonical commands are in
[`launcher/dist/README.md` § "Updating the bundled binaries"](../launcher/dist/README.md#updating-the-bundled-binaries).
The release pre-flight in [`docs/RELEASING.md`](RELEASING.md) points
back at it.

## 6. When to extend this policy

Adding a new path to either column requires:

1. A clear answer to "is the file content the same on every
   developer's machine, or different?" Same → tracked. Different →
   ignored, with the source-of-truth either generated (template
   under `templates/`) or external (e.g. `~/.vct-secrets/`).
2. Updating both `.gitignore` AND this doc in the same PR.
3. If the file should be re-distributed cross-clone via
   `update_orchestrator_at`, double-check that
   `copy_recursive_sync`'s gitignore-aware walker won't drop it
   (write a test if non-obvious).
