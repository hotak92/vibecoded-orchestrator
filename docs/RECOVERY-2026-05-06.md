# Recovery: history rewrite of 2026-05-06

On **2026-05-06** we performed a one-time `git filter-repo` rewrite of
the `main` branch's history to remove 11 paths that contained personal
identifiers and internal procedure documents that should never have
been committed. The set of removed paths is in
`scripts/filter-repo-2026-05-06.sh`. None of the rewritten paths
contained credentials.

A history rewrite changes every commit SHA after the earliest rewritten
commit, so any clone of `vibecoded-orchestrator` made before
**2026-05-06 21:35 UTC** has a divergent history and cannot
fast-forward. This document explains what to do.

## Are you affected?

Run this in your clone:

```bash
git fetch origin
git log --oneline HEAD..origin/main
```

- **No output** → you're clean, nothing to do.
- **Diverged history error**, or the log shows commits you don't
  recognize → you're affected. Continue below.

The launcher's built-in updater (`apply_launcher_update`) uses
`git pull --ff-only`, which **will fail** on affected clones with a
"non-fast-forward" error. You will see this if you click "Update now"
in the launcher's preferences.

## Recovery option 1 — re-clone (recommended)

Simplest, safest. Throws away your local clone (with any uncommitted
changes) and starts fresh.

```bash
# Save anything you don't want to lose first.
# `state/`, `.env`, `~/.vct/`, `~/.vct-secrets/` live OUTSIDE the
# clone and are NOT affected — you don't need to back them up.

# Re-clone:
cd ..
mv vibecoded-orchestrator vibecoded-orchestrator.old
git clone https://github.com/hotak92/vibecoded-orchestrator.git
cd vibecoded-orchestrator

# Re-build the launcher (its prebuilt binary is checked in but you
# may want a fresh local build):
cd launcher
npm install
npm run build
./node_modules/.bin/tauri build --no-bundle
```

After verifying the launcher works, you can delete the old clone:

```bash
rm -rf ../vibecoded-orchestrator.old
```

## Recovery option 2 — hard-reset existing clone

Faster, preserves your `.git/` config (remotes, hooks, etc.) but
**destroys uncommitted changes** in tracked files.

```bash
cd vibecoded-orchestrator

# Stash anything you have uncommitted that you want to keep:
git stash push -m "pre-history-rewrite-2026-05-06"

# Reset main to upstream (this is the destructive step):
git fetch origin
git checkout main
git reset --hard origin/main

# Verify:
git log --oneline -1
# Should print: b555884 chore(privacy): ... (#146)
# (or a later commit if more landed after the rewrite)

# If you stashed earlier and want to recover, try:
git stash list
git stash apply stash@{0}  # may conflict; resolve manually
```

If you have **other long-lived branches** (feature branches, dev
branches) based on the old `main`, you'll need to rebase each of them
onto the new `main`:

```bash
git checkout your-branch
git rebase --onto main <old-base-sha-on-main> your-branch
```

This is harder than option 1 and only matters if you have
work-in-progress branches you can't lose.

## Forks

If you have a fork of `vibecoded-orchestrator`, GitHub will tell you
your fork is "ahead/behind" upstream. To resync your fork to the
rewritten upstream:

```bash
cd your-fork-clone
git remote add upstream https://github.com/hotak92/vibecoded-orchestrator.git
git fetch upstream
git checkout main
git reset --hard upstream/main
git push origin main --force
```

This applies the same rewrite to your fork.

## What the launcher will do in the future

The launcher's auto-update path (`apply_launcher_update`) currently
errors out with "non-fast-forward" on affected clones. A follow-up
will add detection: when the launcher sees a non-fast-forward error
on `git pull`, it'll show a modal explaining the situation and
offering a one-click "Resync now" button that runs `git fetch + git
reset --hard origin/main` for you (preserving `state/`, `.env`,
`~/.vct/`, etc. — all of which live outside the clone). Until that
ships, follow option 2 above.

## Why we did this

Three categories of leakage in pre-rewrite history:

1. **Per-machine `.mcp.json` files** at the repo root and inside
   `launcher/` were committed in earlier launcher subtree work.
   Content includes the original developer's username and a
   personal `KG_COLLECTION` value. No credentials, but personal
   identity should not be in a public repo.
2. **Internal handoff and admin documents** (`HANDOFF-MARTINO.md`,
   `ADMIN_LICENSE.md`, `SECRETS_ROTATION.md`, etc.) leaked
   admin-user identities and procedure detail.
3. **Marketing-scratch docs** (`POSITIONING.md`, `USER_JOURNEY.md`,
   `OSS_LAUNCH_READINESS.md`) — internal early drafts, not for
   public distribution.

No actual API keys, tokens, or credentials were ever committed —
the cleanliness audit report (kept in our internal context) verified
this. The rewrite is a hygiene improvement, not a credential-rotation
emergency.
