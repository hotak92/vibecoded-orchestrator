# Recovery: history rewrite of 2026-05-06

On **2026-05-06** the `main` branch had a one-time `git filter-repo` rewrite. Any clone made before **2026-05-06 21:35 UTC** has a divergent history and cannot fast-forward. This doc explains how to resync.

## Are you affected?

Run this in your clone:

```bash
git fetch origin
git log --oneline HEAD..origin/main
```

- **No output** → you're clean, nothing to do.
- **Diverged history error**, or the log shows commits you don't recognize → you're affected. Continue below.

The launcher's built-in updater (`apply_launcher_update`) uses `git pull --ff-only`, which **will fail** on affected clones with a "non-fast-forward" error. You will see this if you click "Update now" in the launcher's preferences.

## Recovery option 1 — re-clone (recommended)

Simplest, safest. Throws away your local clone (with any uncommitted changes) and starts fresh.

```bash
# Save anything you don't want to lose first.
# `state/`, `.env`, `~/.vct/`, `~/.vct-secrets/` live OUTSIDE the
# clone and are NOT affected — you don't need to back them up.

# Re-clone:
cd ..
mv vibecoded-orchestrator vibecoded-orchestrator.old
git clone https://github.com/hotak92/vibecoded-orchestrator.git
cd vibecoded-orchestrator

# Re-build the launcher (its prebuilt binary is checked in but you
# may want a fresh local build):
cd launcher
npm install
npm run build
./node_modules/.bin/tauri build --no-bundle
```

After verifying the launcher works, you can delete the old clone:

```bash
rm -rf ../vibecoded-orchestrator.old
```

## Recovery option 2 — hard-reset existing clone

Faster, preserves your `.git/` config (remotes, hooks, etc.) but **destroys uncommitted changes** in tracked files.

```bash
cd vibecoded-orchestrator

# Stash anything you have uncommitted that you want to keep:
git stash push -m "pre-history-rewrite-2026-05-06"

# Reset main to upstream (this is the destructive step):
git fetch origin
git checkout main
git reset --hard origin/main

# Verify:
git log --oneline -1
# Should print: b555884 chore(privacy): ... (#146)
# (or a later commit if more landed after the rewrite)

# If you stashed earlier and want to recover, try:
git stash list
git stash apply stash@{0}  # may conflict; resolve manually
```

If you have **other long-lived branches** (feature branches, dev branches) based on the old `main`, you'll need to rebase each of them onto the new `main`:

```bash
git checkout your-branch
git rebase --onto main <old-base-sha-on-main> your-branch
```

This is harder than option 1 and only matters if you have work-in-progress branches you can't lose.

## Forks

If you have a fork of `vibecoded-orchestrator`, GitHub will tell you your fork is "ahead/behind" upstream. To resync your fork to the rewritten upstream:

```bash
cd your-fork-clone
git remote add upstream https://github.com/hotak92/vibecoded-orchestrator.git
git fetch upstream
git checkout main
git reset --hard upstream/main
git push origin main --force
```

This applies the same rewrite to your fork.
